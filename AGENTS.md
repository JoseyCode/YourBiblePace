# AGENTS.md

Rules and context for any AI agent or contributor working in this repo. Rules come first; they are not optional.

## Rules

### No emojis. Ever.
Do not use emojis or emoji-like pictographs anywhere: not in the app UI, strings, code, comments, log messages, tests, documentation,
commit messages, PR descriptions, or replies about this project. This includes symbols that render as emoji on some devices
(for example check marks, clouds, hearts, stars, arrows and dingbats used as decoration).

- For icons in the UI, use Material icons (`androidx.compose.material.icons`) or drawn shapes, never text glyphs.
- For decoration, use drawn shapes, dividers or typography.
- Plain typographic punctuation (apostrophes, quotes, ellipsis, dashes) is fine.

### Other conventions
- Commits follow the Conventional Commit format in the `clean-commit` skill. Plain text only, no markdown, lines at most 150 characters.
- Built APKs always go in `builds/` (git-ignored) and nowhere else. Build them with `tools/build-apk.sh` (see Commands), which names each file
  after its version, like `YBP-1.0.0.apk`. Do not invent other naming schemes. Never leave APKs in the repo root, `app/`, or a temp folder for the user to find.
- Never commit `google-services.json`, keystores, `local.properties` or anything else covered by `.gitignore`.
- Never commit `review.md` or other review artifacts unless asked.
- Reading-progress data is permanent user data. Read `docs/data-model.md` before changing anything in `data/` (Room entity, DAO,
  Firestore document shape). Changes must be additive, and any Room schema change needs a real migration.

## Versioning
Releases are numbered **MAJOR.MINOR.PATCH** and written as `YBP-<version>`, for example YBP-1.0.0. The version lives in one place: the `VERSION` file in the repo root.
`app/build.gradle.kts` reads it for `versionName` and derives `versionCode` from it (`MAJOR*10000 + MINOR*100 + PATCH`, so 1.2.3 is 10203),
and `tools/build-apk.sh` uses it in the APK filename. Never edit `versionCode` or `versionName` directly. Each part is 0 to 99.

- **MAJOR (first number):** breaking changes. A redesign, or anything that changes or migrates people's saved data in a way that can't be
  undone. Reset MINOR and PATCH to 0. Any change to the Room schema or the Firestore document shape that isn't purely additive is a MAJOR bump.
- **MINOR (second number):** new features that don't break anything existing (a new screen, a new Bible version, reading plans). Reset PATCH to 0.
- **PATCH (third number):** small changes: bug fixes, wording, layout and polish tweaks.

Bump `VERSION` before building anything that will be shared, installed on another phone, or uploaded, and commit the bump as
`chore(release): YBP-x.y.z`.

## Project
YourBiblePace is an Android app (Kotlin, Jetpack Compose, Material 3) for reading the whole Bible at your own pace, with progress kept
safe across reinstalls and devices.

- Package `com.example.biblepaceproject`, applicationId `com.joseycode.yourbiblepace` (the applicationId is permanent).
- Theme: a library or archive feel. Parchment, leather brown and gilt gold, all serif type. No dynamic (wallpaper) color.
- Bible texts (KJV, ASV, NHEB; all public domain) are bundled as assets in `app/src/main/assets/bibles/` and generated by
  `tools/build_bibles.py`.
- Progress is stored in Room (source of truth on the device) and synced to Firestore when signed in with Google (optional).
  Contract: `docs/data-model.md`.
- Release signing: the release keystore lives outside the repo at `~/.android/yourbiblepace-release.jks`, and `keystore.properties` in the repo
  root (git-ignored) points to it. Losing either means existing installs can't be updated in place, so both must be backed up by the owner.
- Google sign-in only works for APKs signed with a key registered in the Firebase console. SHA-1 fingerprints:
  debug `79:8B:6B:06:99:F0:65:D7:B4:6D:AF:38:31:45:E2:E6:92:F0:F8:51`, release `52:1A:91:A8:39:BD:8C:78:84:7F:BF:7F:10:B4:B9:58:38:E8:E7:F3`
  (the release one must be added in Firebase before release builds can sign in). Play App Signing will add a third key later.
- Without `app/google-services.json` the app still builds and runs, with cloud sync switched off (no sign-in nudge, and the account sheet says backup is not set up).

## Commands
- Production APK: `tools/build-apk.sh` (or `tools/build-apk.sh release`). Debug APK: `tools/build-apk.sh debug`. Both land in `builds/`. Filename format:
  `YBP-<version>.apk` for release (for example `YBP-1.0.0.apk`) and `YBP-<version>-debug.apk` for debug. Rebuilding the same version replaces the
  file, so bump `VERSION` first if the previous build should be kept.
- Unit tests: `./gradlew :app:testDebugUnitTest`
- Device tests (needs a device or emulator): `./gradlew :app:connectedDebugAndroidTest`
